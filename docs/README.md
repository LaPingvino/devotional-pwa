# Documentation

Working knowledge for the catalog behind the app — what the codes mean, how
identifications are made, and how the pieces fit together.

| document | covers |
|---|---|
| [codes.md](codes.md) | The code system: identity vs structure, mnemonics, punctuation, paragraph-space ownership, and which kind of code a row should get |
| [editorial-method.md](editorial-method.md) | Measurement calibration, text comparison, cross-language placement, known failure modes, and safeguards before a write |
| [architecture.md](architecture.md) | How the matching system is put together |
| [matching-tips.md](matching-tips.md) | Quick lookup: common prayers by header/keyword |
| [workflow.md](workflow.md) | Day-to-day working process |

## Start here

`codes.md` first — most questions that look like data problems are really
questions about what a code is claiming. `editorial-method.md` second, for the
measurements and the ways they mislead.

Both are written to be re-derived rather than memorised: the rules follow from
a small number of ideas, and if a rule ever seems to conflict with the data,
the data is the appeal court.
